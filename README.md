# vdex — 可验证数据交换系统（基础层）

把本地 JSONL 数据集**封版（seal）**为不可变版本，接收方可只取部分记录，并在**不接触发布方存储、不接链、不依赖对象存储**的情况下独立验证记录确实属于该版本。传输通道（文件、消息、U 盘等）可以任意更换，证明与数据的绑定关系不变。

## 安全性质

- **固定版本**：每个版本有清单 `manifest.json`，包含版本号、Merkle 根、记录数、密封时间、前一版本根。版本目录只追加，永不修改。
- **位置即身份**：叶子哈希为 `SHA256("vdex-leaf-v1" || index || record)`。重复内容在不同位置有不同哈希；顺序改变根即改变。
- **证明不能挪位**：证明路径强制校验叶子中的 index 承诺与每一级兄弟节点的左右位置。把某条记录的证明挪到另一个位置会直接失败。
- **发布中断保留旧版**：seal 先写临时目录，成功后原子改名；失败清理临时目录且不推进版本号。新增记录总是生成新版本，旧证明只对旧根有效。
- **独立反拼接验证**：验证器只凭数据包内的清单和证明工作，可检出记录篡改、记录缺失、跨位置重放，以及把其他版本的条目拼进当前包。
- **信任边界在包外**：验证必须显式给出可信根（来自接收方已信任的渠道）。缺少可信根时明确失败——包内自报的清单只能证明自身一致，不能作为认可自己的依据。
- **分批到达，请求先行**：验证请求先固定所需记录集合、版本范围和可信根，材料可分批、乱序、重复到达而不改变要求；内容矛盾的条目双方证据都保留。已核对部分可快照保存、重开接续；只有所需集合全部满足才形成完整结论。请求一旦修改即为新的决定，旧的通过状态不沿用。

```sh
go build ./...
go test ./...
go build -o vdex ./cmd/vdex
```

## 使用

```sh
# 1. 封版 v1（输入每行一条 JSON 记录）
./vdex seal -dataset users -input users.jsonl

# 2. 追加记录后再次封版，生成 v2，旧版保留
./vdex seal -dataset users -input users_v2.jsonl
./vdex versions

# 3. 只导出部分记录（索引从 0 开始，可任意顺序）
./vdex extract -version 1 -indices 0,3,7 -out part.json

# 4. 接收方独立验证（不需要发布方的 store）
#    接收方必须显式给出可信的数据集名、版本、可信根和期望的记录集合；
#    包内自报的清单不能替代这些条件。缺项、多余或重复条目都会失败，
#    并说明是哪一项要求未满足。
./vdex verify -package part.json -dataset users -version 1 -root <可信根hex> -indices 0,3,7

# 5. 同一请求的材料可分批到达：重复 -package 按到达顺序合并，
#    乱序与重复补交不改变要求；只有所需集合全部核对通过才输出 VALID，
#    部分到达输出 INCOMPLETE，矛盾或被拒材料输出 INVALID 并保留证据
#    （原文、到达批次、拒绝依据）。-decisions 指定决定归档目录：
#    已核对部分落盘后可重开接续；修改请求会形成新决定，旧决定的
#    材料与结论仍可用 vdex decisions 查询，不会沿用旧的通过状态。
./vdex verify -package part1.json -package part2.json -dataset users -version 1 -root <可信根hex> -indices 0,3,7

# 6. 查看归档的全部验证决定（含被新请求取代的旧决定）
./vdex decisions -dir vdex-decisions
```

输出行把所需集合明确划分为 `verified` / `missing` / `conflicted`：同一索引先到的可信记录与后到的不同内容会同时保留（含双方原文、到达批次和拒绝依据），重复补交的相同索引、原文和拒绝依据只保留首达证据并计数，不重复堆积证据；不同原文或不同拒绝依据仍独立保存。只要存在缺失、矛盾或被拒材料，整体状态就不会显示 VALID，补齐缺失项也不会清除争议。验证完整通过（VALID）退出码为 0；INCOMPLETE / INVALID 退出码为 1。

## 产物布局

```
vdex-store/
  versions/
    v000000000001/
      manifest.json   # 版本身份（根、记录数、前版根）
      records.jsonl   # 规范化后的原始记录
    v000000000002/
      ...
part.json             # 清单 + 选中记录 + 每条的 Merkle 包含证明
vdex-decisions/        # 接收方决定归档，每个请求指纹一个只追加文件
```

数据包是传输无关的单个 JSON 文件：以后增加任何传输通道，都只是搬运这个文件，证明语义不变。
